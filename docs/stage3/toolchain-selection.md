# Stage 3 toolchain selection and laptop inventory

**Inspection and source retrieval: 8 October 2026.** This is a current, bounded readiness check for the digital project. The older `tool readiness/READINESS.md` dated 4 October is useful history; its unauthenticated GitHub and unbuilt ImplicitCAD statements are superseded by the checks below. No application was replaced and no large optional package was installed for this inventory.

## Decision

Use Python with NumPy for the reproducible closed-loop model and paired studies; add SciPy to the project environment when its ODE, filtering, optimization or statistical routines are actually used. Use the existing ngspice library as an independent electrical transient cross-check. Continue with KiCad for native schematics/PCB work and build123d plus FreeCAD for parametric solids and editable assemblies. Blender remains available for later rendering. These choices cover the present work without paid software or a new student account.

The more detailed tools are conditional additions: NEURON for a specified cable/axon recruitment experiment; Brian 2 for a specified spiking-network experiment; Gmsh with a solver for a specified field or thermal experiment; OpenSim for a specified musculoskeletal experiment. They should answer an explicit model question with defined inputs, convergence checks and comparable outputs. A larger simulator does not supply missing spinal recordings, electrode impedances, recruitment thresholds or learning data.

## Hardware fit and execution strategy

The laptop has an Intel Core i7-13620H, 10 CPU cores/16 logical processors, approximately 15.73 GiB physical RAM, and an RTX 4050 Laptop GPU. `nvidia-smi` reports 6,141 MiB GPU memory and driver 616.92; the GPU's Windows management-interface RAM field is truncated and is not used here. The E: drive had about 554.47 GiB free at inspection. These are observations, not a guarantee for every later workload.

Use CPU, bounded model sizes and streaming summaries for Stage 3. Store paired seed-level metrics and selected raw traces; avoid retaining every channel at every microsecond across every trial. Resolve 50–500 µs electrical pulse edges with event-aligned integration or a convergence-tested fine step, separately from body/sensor time scales. The controller consumes only timed observations; physics truth remains available for evaluation. GPU training is unnecessary for the initial interpretable decoder/control study. A later FEM or cable-model experiment should begin with a small convergence case before allocating long sweeps.

## Additions and unresolved checks

1. **No new CAD/EDA suite is needed to start.** Existing FreeCAD, build123d, KiCad and the bundled ngspice library cover the immediate path.
2. **Project SciPy 1.18.1 has now been added.** It is separate from the existing CAD environment. The implementation records its dependency rather than silently switching into the CAD environment.
3. **A bounded reusable ngspice adapter now passes the actual Stage 3 pair-load comparison.** [The script](../../scripts/stage3_ngspice_check.py) and [recorded receipt](../../results/stage3/ngspice-crosscheck.json) compare cathodic/anodic ideal current, open gap, and both open and switched passive recovery at two maximum time steps. Maximum waveform error was about 1.1 nV, within the declared 2 µV numerical criterion. This corroborates the linear equations, not electrode chemistry or current-servo hardware. A missing `spinit` warning and untested vendor/XSPICE model loading remain. The adapter copies vector values before a subsequent `ngGet_Vec_Info` query, which can overwrite shared vector metadata. Its `--library` option supports another installation; a portable run without a library explicitly skips unless `--require-library` is supplied. Default runs print results; `--output` deliberately saves a new receipt.
4. **No mandatory Brian 2, NEURON, Elmer or OpenSim installation yet.** Install a selected tool only alongside the experiment it enables, with a smoke test, license record and environment instructions. Their present absence does not block reduced-order full-loop simulations.
5. **Ansys remains partly verified.** The original-media files `python_site_syscplg/WINX64.7z` and `tp/cudss/WINX64.7z` are still absent. Workbench presence and earlier startup do not prove every installed solver works.
6. **Reference workflow checks remain separate.** Zotero sync/import and OCP Viewer's interactive GUI were not retested. They are useful review interfaces, not prerequisites for the current numerical study.
7. **Target firmware tools will be a later addition.** A stable Zephyr/Nordic-supported build environment is needed if Stage 4 produces nRF5340 firmware. Record actual app/network-core RAM and flash occupancy, test project logic on the host where appropriate, and preserve the difference between simulated deadlines and measured hardware timing. A fully digital project can deliver target binaries and testable control logic without pretending that a host simulator proves on-device operation.

This tool selection supports a digital study of the proposed implant mechanism. It does not convert assumed biological transfer functions into established effects or certify a finished implant.
